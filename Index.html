05

Analysis process

How this report was built, from raw paper forms to verified findings.

Step 1
Survey design
Designed pre and post instruments with matched themes, closed-ended questions, and an identifier system for future editions.
Step 2
Data entry & cleaning
Extracted 120 responses from original source files. Identified and corrected a column-shift error and a fabricated matching system.
Step 3
Quantitative analysis
Used COUNTIFS, AVERAGEIF, INDEX MATCH and SUMPRODUCT across 9 structured Excel sheets to calculate all indicators.
Step 4
Qualitative coding
Read and themed all 60 open-text responses across 3 questions. Single-coder categorisation with disclosed limitations.
Step 5
Impact report
9-section Word report with embedded charts, data integrity note, and a full appendix documenting every correction made.
Step 6
Interactive dashboard
Live Excel dashboard with school-level filtering and formula-driven KPIs, plus this standalone HTML portfolio page.
06

Recommendations

Programming
  • Investigate the group challenge at CMS, which scored 0.53 below the overall average
  • Prioritise laptop availability and schedule buffer time for the next edition
Targeting
  • Target schools with lower baseline tech exposure, where relative gains are largest
  • Add a segment on women in tech, as role model awareness was the weakest baseline metric at 46.7%
Programme growth
  • Use the 20pp career interest shift to support funding conversations
  • Replicate at additional schools with similar baseline profiles
  • Run a follow-up check 4 to 8 weeks post-event to validate stated intentions
Research & M&E
  • Collect a real participant identifier on both forms going forward
  • Verify every column against the original source before reusing any cleaned file
  • Use identical wording for any pre/post item intended for direct comparison
